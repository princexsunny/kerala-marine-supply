## Visual direction

- Clean, editorial, high-contrast. White / off-white background (#f3f2f2 range),
  near-black text (#201e1d range), one strong red-orange accent (#c0392b range).
- **Custom line illustrations** in the accent red with black details: lighthouse,
  fishing boats, trawler, crane, cargo ship, fish, cold-chain truck, nets, wind
  turbine, recycling, microscope, umbrella/beach. Thin consistent stroke weight,
  flat, no gradients, no photography in the illustrations.
- Repeating thin wavy-line motif for water beneath the illustrations.
- Bold heavy sans for headings (tight letter-spacing, ~-0.03em), regular
  humanist sans for body.
- Cards: white, thin light border, generous padding, small icon + title +
  one-line description + chevron.
- Section headers: small red underline stroke beneath the heading.
- Buttons: solid red primary with white text; outlined secondary.

## Responsive requirement — important

Build **one responsive website**, not a separate native app. It must work as a
mobile web page opened from a WhatsApp link.

- **No onboarding/splash carousel.** Visitors arriving from search or a shared
  link must see real content immediately.
- No app chrome: no back arrows, no share icons, no notification bell (the
  browser already provides these).
- A sticky bottom navigation bar on mobile is acceptable, but every destination
  must also be a normal, linkable URL.
- Venture grid: 6 across on desktop, 3 on tablet, 2 on phone.
- Test at 360px width.

## ADMIN — `/admin.html` and `/login.html`

**This already exists and works. Restyle it to match the new design if you like,
but do not change its behaviour or the API contract.**

Sign-in at `/login.html` with a password (session cookie). `/admin.html`
redirects there when signed out. Sign-out button in the admin header.

Four steps:

1. **Photographs** — five slots: `hero`, `photo1`, `photo2`, `photo3`,
   `founder`. Images are downscaled in the browser (2000px long edge) then sent
   as `PUT /api/media` with a flat `{ slotKey: dataURL }` body. Max 15 MB each.
   JPEG/PNG/WebP/GIF.
2. **Video** — one home-page video. `POST /api/media/video` (multipart, field
   `file`), `DELETE /api/media/video`. Max 150 MB. MP4/WebM/OGG/MOV only. Show
   upload progress percentage.
3. **Documents** — library with categories: Licences, Agreements & LOIs,
   Quotations, Investor, Photos & plans, Other. `POST /api/documents`
   (multipart: `category`, `file`), `GET /api/documents`,
   `DELETE /api/documents/:id`. Max 200 MB. Drag-and-drop plus file picker.
4. **Job applications** — table of submissions with resume links.
   `GET /api/applications`, `DELETE /api/applications/:id`.

Delete actions confirm first and cannot be undone.

### The home page must display admin-uploaded media

The five photo slots and the video are shown on the home page by fetching the
public endpoint `GET /api/media`, which returns:

```json
{ "hero": { "url": "...", "contentType": "image/jpeg" },
  "photo1": { "url": "..." },
  "video":  { "url": "...", "contentType": "video/mp4" } }
```

Give each photo location a stable element id so a script can fill it. Photos
must render in **full colour** — do not apply a grayscale filter.

If the new hero is an illustration rather than a photograph, say which slots
remain in use so unused ones can be removed from the admin.
